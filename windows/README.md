# Nashi for Windows

Mac and Windows 0.7.5 are published with the shared 45-format / 27-tool catalog and aligned Home, Library, paste, preview and window-management workflows. See [the feature parity and verification matrix](FEATURE-PARITY.md) for implementation, evidence and platform differences.

Nashi uses WPF / .NET 10, the same pear artwork, file garden, rounded cards, gold actions and light/dark palette as macOS, with Windows keyboard conventions and native window controls. Build with `dotnet publish windows/Nashi.Windows -c Release -o build/windows/Nashi`. The output is self-contained; users do not install .NET separately. Keep the portable folder together in a writable location so updates can replace it safely.

The shared catalog contains 27 tools and 45 input formats. It includes photo editing, framing/collages, crop/annotation/redaction, QR/PDF tools, document/Pages/EPUB/spreadsheet/slides conversion, archives/subtitles, media tools and public web downloads. Runtime setup is available from Home. Download URLs and SHA-256 hashes are pinned in `Toolchain.cs`, `OfficeRuntime.cs` and `MetadataService.cs`; upstream licenses remain separate from Nashi's MIT license. See [third-party notices](THIRD-PARTY-NOTICES.txt).

Library and preferences live in `%LOCALAPPDATA%/Nashi`, outside the portable application folder. Library keeps the last 50 successful exports and clipboard imports. Text imports use UTF-8 and image imports use lossless PNG. No clipboard monitoring runs in the background. Signed public update staging verifies the manifest, archive hash, version and trusted signature before restart.

While dragging in Explorer or another application, **Ctrl** opens tools, **Shift** conversion and **Alt** file actions. Settings can change the three chords. **Ctrl+Shift+D** opens a copied public media link. The app can remain in the system tray.

## Light resident mode

Nashi starts at sign-in straight into the tray (`Nashi.exe --background` in `HKCU\…\Run`; Settings › General › *Launch at login* turns it off and is remembered). Until you open the window, only the tray icon, the drag gesture, window management and hourly update checks are loaded; the main window, Library, thumbnails and media engines are created on demand and released again — with the working set trimmed — when the window goes back to the tray. The drag gesture is event driven: a low-level mouse hook on its own thread only records button presses/releases (and moves while a button is held) and never blocks; modifier checks run only between a drag crossing the 10 px threshold and the release, at the same 40 ms cadence as before, so the wheel looks and opens exactly as before while an idle Nashi does no periodic work. If the hook cannot be installed, the previous 40 ms polling is used. *Keep running in the system tray* still decides whether closing the window keeps Nashi (and the gesture) alive.

Measured on an isolated desktop (Windows 11, `--background`, 3-minute sample after a 1-minute settle): before 204 MB working set / 124 MB private bytes and 391 ms CPU (the 40 ms poll); now 13 MB working set (15 MB peak) / 78 MB private bytes and 31 ms CPU (two 15.6 ms scheduler ticks). The working set rises while converting (about 105 MB) and is trimmed again 20 s after the work ends (about 10–13 MB).

## Explorer menu and command line

`Nashi.exe --convert FORMAT FILE…` converts with the saved export profile for FORMAT (the same path as "Convert to FORMAT" on the wheel), shows a small progress toast and saves next to the source (or wherever Settings › Folders says), then exits; if Nashi is already running the request is handed to it instead. `--files-from LIST` reads one path per line for very large selections. `Nashi.exe --wheel FILE…` opens the tools wheel at the pointer (file actions for folders). Requests that arrive together — one process per file from the classic menu — are merged into one job, and files that cannot become FORMAT are skipped with a notice.

* **Windows 11 top-level menu:** *Convert with Nashi* (submenu of the formats valid for every selected item, from `FeatureCatalog.Formats`) and *Nashi tools…* (Turkish: *Nashi ile dönüştür*, *Nashi araçları…*, following the app language). They come from `NashiShell.exe`, a small out-of-process `IExplorerCommand` COM server published next to `Nashi.exe` and registered by a signed sparse package (`windows/Packaging/AppxManifest.xml`, `com:ExeServer` + `desktop5` verbs for `*` and `Directory`). It routes requests to the running Nashi over its single-instance pipe (or starts `Nashi.exe --convert`), and exits after two idle minutes.
  Build it without administrator rights with `windows/Packaging/build-sparse-package.ps1 -InstallDirectory <portable folder>`: it creates (or reuses) the self-signed `CN=Nashi Local Signing` code-signing certificate in `Cert:\CurrentUser\My` with a non-exportable private key, exports only the public `.cer`, packs and signs `Nashi.ExplorerMenu.msix`, and writes `install-explorer-menu.ps1` (run once, elevated: trusts the `.cer` in `LocalMachine\TrustedPeople` and runs `Add-AppxPackage -ExternalLocation`) and `uninstall-explorer-menu.ps1` (removes the package and the trust; `-RemoveSigningKey`, `-RemoveClassicMenu`). Portable updates must keep `NashiShell.exe` in the folder for this menu to keep working.
* **Classic menu (fallback, "Show more options"):** per-user `HKCU\Software\Classes` verbs — *Convert with Nashi* for each convertible extension with exactly its formats, and *Nashi tools…* for files and folders. Nashi keeps them pointing at its current folder; Settings › General › *Show Nashi in Explorer's right-click menu* removes them. They work without the package.

**Ctrl+O** chooses files; **Ctrl+V** imports files/text/images/links outside text fields; **Ctrl+1/2** switches Home/Library; **Ctrl+F** searches; **Ctrl+U** checks updates. **Ctrl+Space** opens the selected files' tools wheel. Arrows/Tab choose a tool, Enter opens it and Escape closes it.

Media editors use **Space** for play/pause, **Left/Right** for one-second seeking, **Shift+Left/Right** for frame steps, **I/O** for range marks and **Shift+Space** to play the selected range. Crop supports drag, Shift ratio lock, selection move/resize, aspect presets and Enter save. Annotation supports Select/Move, Delete and Ctrl+Z. Normal text-field editing is preserved.

`Nashi.Verify` checks the shared engine and security foundation. `Nashi --smoke-test` runs real Windows keyboard, clipboard, OLE drag, Library, editor and export checks and writes diagnostic JSON/PNG artifacts. See [verification details](FEATURE-PARITY.md#commands-and-evidence) before interpreting a CI artifact as a completed test or official release.
